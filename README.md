# IVY大分 ARスタンプラリー(C TEC FES)

マーカー(ポスター)をスマホのカメラで読み取ると、問題が出るスタンプラリーです。
MindAR + A-Frame を使い、GitHub Pages で動かします(サーバー不要・インストール不要)。

## フォルダの見方
| 場所 | 中身 | 触る場面 |
|---|---|---|
| `index.html` | カメラ画面(ここから開始) | ふだん触らない |
| `goal.html` | スタンプ帳・景品の確認画面 | 文言を変えたいとき |
| `debug.html` | マーカーの診断ページ | 読み取れないとき・順番確認 |
| `reset.html` | 記録リセット用ページ(係の人用QRの行き先) | ふだん触らない |
| `spots/` | 9つの問題ページ(HTML) | 問題の文章を変える |
| `css/` | 見た目(`common.css`=共通、`spots/`=問題ごと) | 色・大きさを変える |
| `js/config.js` | **設定(暗証番号・景品数・マーカー順)** | まずここを見る |
| `js/common.js` | 全問題で共通の動き(まちがい数・クリア記録) | ふだん触らない |
| `js/spots/` | 問題ごとのゲームの動き・答え | 答えや数字を変える |
| `ar/all.mind` | マーカーの読み取りデータ | マーカーを変えたとき作り直す |
| `markers/` | 印刷用マーカー画像9枚(白ベース) | 印刷する |
| `docs/` | 引き継ぎ資料 | 困ったとき |

## 自分のパソコンで試す
フォルダで `python -m http.server 8000` を実行し、ブラウザで http://localhost:8000/ を開く
(または VS Code の Live Server)。カメラはスマホ実機・https でないと動かないので、
画面の確認は PC、読み取りの確認は公開後にスマホで行います。

## 公開
GitHub の Settings → Pages で `main` ブランチ / `(root)` を指定。公開URLは
`https://<組織名>.github.io/<リポジトリ名>/` になります(無料プランではリポジトリを Public に)。

## 注意事項

### 受付を通らずにスポットのQRから入れない仕組み(受付チェック)
- **受付のQRコード(スタート用。`index.html` を開くQR)を先に読んだ端末だけ**が、スポットのQR(`q/1/`〜`q/9/`)から問題ページを開けます。
  受付を通らずにスポットのQRを読んだ端末には、「受付のQRコードを、先に読み取ってください」という案内画面が出ます。
- 仕組み: `index.html` を開くと、スマホのlocalStorageに「受付済みの印」(`ivyArStampStarted`)が付きます(`js/hub.js`)。
  問題ページを直接開いたとき、`js/common.js` がその印を確認します。印がなければ案内画面を出し、問題は始まりません(開始時刻も付けません)。
- `index.html` の中で開かれる問題ページ(`?embed=1`)は、すでに受付済みなのでチェックしません。マーカー読み取りは、もともと `index.html` の中だけで動きます。
- **`reset.html`(記録リセット用)を開くと、この印も消えます。** リセットした端末は、受付のQRを読み直すまで、スポットのQRから入れません。
- スタンプの記録(クリア記録・まちがい回数)は、受付のQRを読み直しても**消えません**(消えるのは `reset.html` と `?reset=1` だけ)。

### localStorage が使えない端末は、チェックしない(入れる側に倒す)
- プライベートブラウズや、保存を禁止した設定など、localStorage に書き込めない端末では、受付チェックを行わず、そのまま問題を開けます。
  **入れない人を出さないための方針**です(この場合、受付を通らずに入れる端末が残りますが、ごく少数と考えています)。
  書き込みできるかは、`js/common.js` の `storageWorks()` で確かめています。

### 受付チェックで案内画面が出てしまう、受付済みの人
- 受付のQRとスポットのQRを、**別のアプリ・別のブラウザ**で読むと、保存場所が別になり、印が見えません(例:iPhoneのカメラ→Safariで受付、LINE内でスポットのQR)。
  案内画面にも書いてあるとおり、**最初に使ったアプリ(iPhone=Safari、Android=Chrome)で、受付のQRをもう一度読んでもらってください。**
- 動作確認で、スポットのページを直接開きたいときは、先に一度 `index.html` を開いてから開く(または `?embed=1` を付ける)。

### マーカーの印刷物
- すべてのマーカーの余白に、赤い文字で「受付でQRコードを読み込んでからしかARマーカーは読み取れません」と入れています(A4印刷用)。
  `markers/` の画像(`all.mind` の元)は変えていません。余白に文字を足すときは、マーカーの絵の部分にかからないようにしてください。
